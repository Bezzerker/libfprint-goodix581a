# goodix581a — драйвер Linux для сканера отпечатков Goodix 27c6:581a

[English version](README.md)

Драйвер [libfprint](https://gitlab.freedesktop.org/libfprint/libfprint) для
USB-сканера отпечатков Goodix `27c6:581a`, который стоит в
**Xiaomi Mi Notebook Pro 15.6" 2021 (Ryzen Edition)**. Goodix выпускала для
этого сенсора только драйвер под Windows. Этот драйвер восстановлен по
Windows-драйверу и по исследованиям goodix-fp-dump. Он подключается к обычному
стеку `libfprint` + `fprintd`, поэтому запись отпечатка, проверка и вход через
PAM работают так же, как с любым поддерживаемым сканером.

| | |
|---|---|
| Сенсор | Goodix USB `27c6:581a`, прошивка `GFUSB_GM168SEC_APP_10035` (семейство 52xd «Milan HV») |
| Изображение | 64 × 80 пикселей, около 500 dpi (примерно 3,2 × 4 мм) |
| Стек | libfprint 1.94.100 + `goodix581a`, fprintd 1.94 |
| Сравнение | на компьютере (в сенсоре сравнения нет), собственная реализация SIFT |

> **Статус: экспериментальный.** Проект не связан с Goodix или Xiaomi. При
> первом использовании драйвер может записать в сенсор ключ TLS (см.
> [Ключ сопряжения](#ключ-сопряжения-psk)). Используйте на свой риск.

## Что работает

- Сессия с сенсором: TLS 1.2 PSK, загрузка конфигурации, получение снимка.
- Определение касания и отрыва пальца встроенным детектором сенсора (FDT).
- Запись отпечатка (20 касаний), проверка и опознание через `fprintd`.
- Вход через PAM (`pam_fprintd`), например для `sudo`.

## Точность — прочитайте до включения PAM

Сенсор видит около 3 × 4 мм, то есть малую часть подушечки пальца. Если касание
пришлось на участок, которого нет ни в одном из 20 снимков записи, сравнивать
не с чем, и никакой порог этого не исправит.

| Измерение | Результат |
|---|---|
| Записанный палец через fprintd, одно касание | принимается в ~50–60 % случаев |
| Записанный палец, 3 попытки (по умолчанию в `pam_fprintd`) | ~90 % (оценка) |
| Чужие пальцы через fprintd | 0 из 12 приняты |
| Чужие пальцы, записанные наборы (56 попыток) | максимум 4 очка при пороге 10 |

Цифры получены на небольшом объёме тестовых данных одного человека, так что
реальная доля ложных допусков может быть порядка 1–2 % на попытку.
**Используйте отпечаток как удобство, а пароль оставьте основным способом
входа.** Каждый дополнительный записанный палец примерно пропорционально
повышает шанс ложного допуска, поэтому хватит одного-двух пальцев.

## Состав репозитория

```
driver/          драйвер для libfprint
  goodix581a.c     протокол, TLS, определение пальца, захват, запись/проверка (FpDevice)
  sigmatch.c/.h    ключевые точки SIFT (порт SIFT из OpenCV) + геометрическое сравнение
  integrate.sh     добавляет драйвер в исходники libfprint 1.94.x
pkg/PKGBUILD     пакет Arch Linux libfprint-goodix581a (заменяет libfprint)
tools/           инструменты исследования и тестов на Python/C (см. «Разработка»)
```

## Установка

### Arch Linux и производные

Пакет — это libfprint 1.94.100, собранный из исходников с добавленным
драйвером. Он объявлен как `provides` и `conflicts` для `libfprint`.

`-s` поставит зависимости для сборки, а `-r` удалит их после неё:

```bash
cd pkg
makepkg -sri
```

Затем установите fprintd:

```bash
sudo pacman -S fprintd
```

Если fprintd уже работал, перезапустите его, чтобы он загрузил новую
библиотеку:

```bash
sudo systemctl restart fprintd
```

### Другие дистрибутивы

Добавьте драйвер в исходники libfprint 1.94.x и соберите их так же, как ваш
дистрибутив собирает libfprint. Сначала скачайте libfprint и встройте драйвер:

```bash
git clone -b v1.94.100 https://gitlab.freedesktop.org/libfprint/libfprint.git
sh driver/integrate.sh libfprint
```

Затем настройте и соберите. Драйверу нужен OpenSSL, его подключает помощник
`openssl`, который регистрирует `integrate.sh`:

```bash
meson setup build libfprint -Ddrivers=all -Ddoc=false -Dinstalled-tests=false
meson compile -C build
```

При сборке с `-Dintrospection=false` в `tests/meson.build` libfprint 1.94.100
нужна однострочная правка из `pkg/PKGBUILD`.

Лучше собрать из результата пакет, чем ставить его поверх libfprint вашего
дистрибутива.

### Ключ сопряжения (PSK)

Сенсор шифрует снимки TLS-сессией с заранее известным ключом, который хранится
в самом сенсоре. Драйвер использует ключ из нулей. Если в сенсоре другой ключ,
например записанный Windows-драйвером, драйвер заменяет его при открытии
устройства. Ключ пишется в рабочем режиме прошивки, без её стирания. Если потом
установить Windows-драйвер Goodix, он запишет свой ключ, а этот драйвер после
возвращения в Linux снова его заменит.

## Использование

Запишите палец (20 касаний). Касайтесь естественно, так же, как будете потом
разблокировать, и слегка сдвигайте и поворачивайте палец между касаниями.
Нарочно обходить зоны пальца (центр, кончик, края) хуже: снимки ложатся
слишком редко.

```bash
fprintd-enroll -f right-index-finger
```

Проверить палец:

```bash
fprintd-verify
```

Показать записанные пальцы:

```bash
fprintd-list $USER
```

Удалить все отпечатки (с `-f <палец>` удаляется только один):

```bash
fprintd-delete $USER
```

### sudo по отпечатку

Добавьте `pam_fprintd` в `/etc/pam.d/sudo`. Команда сохранит копию исходного
файла:

```bash
sudo sed -i.bak '2i auth      sufficient    pam_fprintd.so max-tries=3 timeout=15' /etc/pam.d/sudo
```

Благодаря `sufficient` sudo спросит пароль, если отпечаток не подошёл или
сканера не коснулись за 15 секунд. Ctrl+C во время ожидания отменяет весь sudo.
Откат:

```bash
sudo mv /etc/pam.d/sudo.bak /etc/pam.d/sudo
```

## Как это устроено

**Протокол.** Сенсор относится к семейству Goodix «52xd» (MCU MSP430), как
описано в [goodix-fp-dump](https://github.com/goodix-fp-linux-dev/goodix-fp-dump).
Обмен идёт 64-байтными пакетами по bulk-точкам `0x01`/`0x83`. Внутри пакета
лежит сообщение `[cmd, len, payload, checksum]`, на каждую команду сенсор
отвечает подтверждением `0xb0`. Открытие устройства:

1. Проверить версию прошивки и хэш PSK; при необходимости записать нулевой PSK.
2. Сбросить сенсор (`0xa2`) и выполнить TLS-рукопожатие. Сенсор выступает
   TLS-клиентом, компьютер сервером (PSK-AES128-CBC-SHA256). Записи TLS идут
   в пакетах `0xb0`.
3. Загрузить 256-байтную конфигурацию сенсора из Windows-драйвера (`Wbdi.dll`
   3.0.81.320). Драйвер подставляет в этот шаблон поле TCODE и пересчитывает
   контрольную сумму, иначе сенсор её отвергает.

**Снимок.** Команда `0x20`, режим `01 03`, DAC `0x127`. Ответ приходит
пакетом `0xb2`, зашифрованным TLS: 7680 байт данных, 12-битные пиксели по 4 на
6 байт. Драйвер вычитает фон пустого сенсора и растягивает контраст до 8 бит
между 1-м и 99-м перцентилями.

**Определение пальца.** По яркости снимка палец не отличить от следа, который
он оставляет. Поэтому драйвер опрашивает встроенный детектор сенсора (FDT,
`0x36`): 8 уровней, которые у пустого сенсора меняются не больше чем на 2, а с
пальцем на 90–120. Касание засчитывается при изменении на 40, отрыв при
изменении на 15, и каждое должно держаться 2 показания подряд. Фон пустого
сенсора и база детектора сохраняются между закрытием и открытием устройства:
fprintd открывает сенсор заново на каждую попытку, и палец к этому моменту
часто ещё лежит на сенсоре. После 60 секунд простоя они сбрасываются, потому
что за это время меняется температура.

**Сравнение.** Минуции NBIS (bozorth3) на таком маленьком снимке бесполезны:
находится всего 0–12 точек. Поэтому драйвер использует свой SIFT, точный порт
SIFT из OpenCV:

- снимок увеличивается вдвое, извлекается до 150 ключевых точек;
- точки сопоставляются тестом Лоу (0,75);
- полный перебор пар точек ищет жёсткое преобразование, согласованное с
  сопоставлением (допуск 2 пикселя, масштаб ±15 %, согласованность ориентаций
  20°).

Оценка — сумма по 20 снимкам записи величины `max(0, совпавшие_точки − 3)`,
отпечаток принимается при 10. Шаблон хранится в `fpi-data` отпечатка (`(uaay)`,
по одному блоку на снимок) и сравнивается на компьютере.

## Разработка

Python-инструментам нужен `pyusb`, а скриптам оценки ещё и `numpy`:

```bash
python -m venv .venv && .venv/bin/pip install pyusb numpy
```

Инструменты обращаются к сенсору напрямую. На время работы с ними остановите
fprintd и запускайте их от root или дайте своему пользователю доступ к
USB-устройству. Инструменты, которые читают конфигурацию сенсора или прошивку,
ожидают `Wbdi.dll` из Windows-драйвера Goodix 3.0.81.320. Он не входит в
репозиторий; укажите путь к нему в переменной `WBDI`.

- `tools/probe.py` только читает: показывает версию прошивки и хэш PSK.
- `tools/provision.py`:
  - `build-fw` извлекает прошивку 10035 из `Wbdi.dll`;
  - `psk-app` записывает нулевой PSK.
- `tools/capture.py`, `tools/stream.py`, `tools/fdt_stream.py` — прототип
  захвата и диагностика детектора пальца. Отладочные снимки пишутся в `out/`
  (переопределяется переменной `OUT`).
- `tools/collect.py N DIR` собирает размеченный набор снимков `.raw` (int16
  80×64, снимок минус фон).
- `tools/sigeval.c` прогоняет сравнение по файлам `.raw` и выводит матрицу
  «совпавшие/кандидаты».
- `tools/eval_ds2.py` сравнивает правила подсчёта оценки по такой матрице:
  20 снимков записи, 15 своих, затем чужие.

Сборка программы для прогона сравнения:

```bash
gcc -O2 -o sigeval tools/sigeval.c driver/sigmatch.c -lm
```

Прогон по своим снимкам:

```bash
./sigeval 150 enroll/*.raw genuine/*.raw impostor/*.raw
```

Оценки `sigeval` в точности совпадают с оценками живого драйвера. Если собрать
драйвер с `-DGOODIX581A_DUMP` и задать `GOODIX581A_DUMP=<каталог>`, он будет
сохранять каждый снимок как `.raw`. Чтобы видеть в журнале оценку каждого
сравнения, задайте `G_MESSAGES_DEBUG=all`.

Наборов отпечатков в репозитории нет: это биометрические данные.

## Удаление

В Arch, если libfprint до этого не был установлен:

```bash
sudo pacman -Rns fprintd libfprint-goodix581a
```

Если libfprint нужен другим программам, установите вместо этого пакет из
репозитория, он заменит этот:

```bash
sudo pacman -S libfprint
```

Нулевой PSK останется в сенсоре. Он нужен только этому драйверу и
Windows-драйверу Goodix, а Windows-драйвер при установке заменяет его своим.
